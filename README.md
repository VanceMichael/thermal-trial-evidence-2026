# 并入混合热源时的测计覆盖和重采

这里的资料由本地来源模拟器提供，编号、参与方和历史业务记录全部为合成数据。运行环境为 Node.js 22.23.4，监听地址默认为 `127.0.0.1:8700`，可用 `PORT` 调整端口。

```sh
npm run source
```

另开终端运行 `npm test` 可检查来源契约。测试以独立临时端口启动来源。

两版业务记录和取件字段见 [资料格式](source/formats.md)。`POST /control?edition=r2` 模拟业务方更换当期资料，切回 `r1` 可重新查看初始来源。

## 值班采集工具

`duty/` 是值班侧的采集工具：几个试验一起登记，按留存窗与共用额度取得该留的原包，认定读数并办理验收与交接。

```sh
# 一轮采集：登记 → 对账 → 领取 → 认定 → 测计/验收 → 交班（状态存于 --state 目录）
node duty/cli.mjs collect --source http://127.0.0.1:8700 --state var/duty
# 重打最近交班凭据
node duty/cli.mjs handover --state var/duty
```

行为要点：

- 同一流道的采样头可处于不同启动代与采样节拍，各自时域内真正保留的原包分别收回；已备份原件（`saved`）免费复用，不占采集额。
- 同一班的读取额度按网关设备代共用；需求合并去重（同一包支持多个试验），按“更早失去的来源窗先收、同界依计划优先序”领取。
- 未签动作只保护即将被覆盖的原料，不提前交作测计；取消的动作不删在库原件。
- 读数按现场对时与生效校准认到工况：掉样、尚未收到适用校准、真正读到零值分别标记；每个现场秒两个方向各至少两个有效且有适用校准的读数才出该段测计依据，全覆盖且已签才给验收领取。
- 对时或校准补交时，在库原包按新资料重新认定即可支持另一时段，无须向网关重复领取；留存已越过的在库包标记“在库保护”。
- 网关先到前几页再报越期/限额时，已到数据照常入库；交班凭据留出已拿到的包、仍应尝试的缺口与已失去的时段。
- 动作调整、探头更换或校准更正推翻已交结论时，给出原交接凭据及各时段处置（确认中/待校准补交/掉样不足/可补领/已失去）。
